# Battle simulation (Twinleaf bots) — pilot

Question: do Twinleaf's bots, playing each other with real tournament lists, reproduce real matchup
win rates for the current format (TEF-30C)? **Short answer: no.** Across 55 non-mirror pairs with
≥20 real matches, sim and real win rates are uncorrelated (Pearson 0.01 for both bots; 0.07 / 0.17
on the 41 pairs with ≥100 real matches), the mean absolute gap is about 24–25 percentage points,
and only 16 (simple) / 13 (advanced) of 55 pairs land within 10 points. Do not use these numbers as matchup evidence.

## Files

| file | what |
|---|---|
| `twinleaf_TEF-30C.json` | per bot: summary (games, error rate, first-player win rate, calibration stats) and per pair: games, wins, losses, draws, errors, win rate overall / going first / going second, average turns, real record from `data/selection/selection_TEF-30C.json` |
| `games/*.jsonl` (not committed, regenerated by `run.js`) | one line per game: decks, seed, who went first, winner, turns, end reason, prizes and deck left |

Code and instructions: `sim/twinleaf/` (runner, deck picker, summariser, setup scripts).

## How it was run (2026-10-05)

* Engine: Twinleaf (twinleafgg/twinleafgg, MIT) at commit `7bb4573`, compiled locally; headless runner
  `sim/twinleaf/run.js` drives Twinleaf's `Store` directly (no server, no DB). Seeded shuffles and
  coin flips; seats alternate who goes first.
* Decks (`sim/twinleaf/decks.json`): best-placing Frankfurt 2026-09-26 list for each of the 5
  recommended decks (basic-box-m, alakazam-dusknoir, crustle-dri, dragapult-ex, slowking-scr) and the
  12 archetypes in `data/archetypes/`. All 60-card lists map to Twinleaf cards with no substitutions.
* 60 pairs (5 × 12, four of them mirrors).
  * simple bot (`SimpleTacticsAi`): 200 games per pair, 12,000 games, ~0.6–0.9 games/s per core.
  * advanced bot (`ActionSearchAi`, beam search + a Dragapult playbook applied to every deck): about
    one game per 25–35 s per core, so 21–23 games per pair, 1,317 games. The first 597 games ran
    without the loop breaker (8.5% hit the 3-minute cap, mostly ability loops), the other 720 with
    `--loop-limit 5` (0.3% capped; 89 games had a turn ended by the breaker).
* Real side: match records (Bo3) from TEF-30C + TEF-PBL windows, `W/(W+L)` with ties dropped.
  Sim is per game. Converting sim game rates to Bo3 match rates makes the gap larger, not smaller.

## Results

| | simple bot | advanced bot |
|---|---|---|
| games (per pair) | 12,000 (200) | 1,317 (21–23) |
| capped / error rate | 1.5% | 4.2% |
| pairs compared (≥20 real matches, no mirrors) | 55 | 55 |
| Pearson r, sim vs real | 0.01 | 0.01 |
| Pearson r, 41 pairs with ≥100 real matches | 0.07 | 0.17 |
| mean absolute difference | 0.247 | 0.241 |
| pairs within 10 pp | 16 | 13 |
| same side of 50% | 27 / 55 | 32 / 55 |
| first player win rate | 52.3% | 62.6% |

The two bots agree with each other (r = 0.71 across pairs), so the sim measures something stable,
but it is not the real game. Average win rate of each recommended deck across its 12 opponents
(sim simple / sim advanced / real, real weighted by matches): Alakazam Dusknoir 0.44 / 0.38 / 0.57,
Basic Box 0.46 / 0.68 / 0.53, Crustle 0.87 / 0.88 / 0.57, Dragapult 0.62 / 0.49 / 0.51,
Slowking 0.22 / 0.47 / 0.51. Per-pair table: `python sim/twinleaf/summarize.py`.

Answering "yes" vs "no" to optional prompts barely matters: a 20-game-per-pair simple-bot run with
stock `--confirm no` correlates 0.92 with the default run and −0.05 with real results.

## Why the sim is off (seen in game logs)

* Games are lopsided: in about two thirds of simple-bot games the loser takes no Prize card.
* Crustle (DRI 12, walls Pokémon ex attacks) wins 87–89% overall in sim versus 57% in reality —
  the bots barely ever switch to non-ex attackers, tech answers, or Gwynn/Xerosic lines.
* Slowking (copy-attack deck) wins 22% with the simple bot; it needs planning the bots don't do.
* Ability loops (advanced bot): re-activating an ability and cancelling its prompt forever in one
  turn (Mew ex Memory Helix, Munkidori Adrena-Brain). Fixed in the runner by `--loop-limit`.
* Stalling loops: both bots repeatedly use Academy at Night (put a card from hand on top of the
  deck, draw it next turn) and pass without attacking; advanced-bot Dragapult did this for 20+
  turns in one sampled game. Capped games (80 turns or 3 minutes) count as errors and are
  excluded from win rates.
* The advanced bot's evaluator includes a Dragapult-only playbook bonus regardless of deck.
* Twinleaf's stock bots answer "no" to every optional "you may" prompt; the runner answers yes
  (`--confirm no` restores stock behaviour; a 20-game-per-pair check is in the pilot report).

## Card spot-checks (Twinleaf source vs printed text)

Alakazam MEG 56 (Psychic Draw, 2 counters per card in hand; attack is named "Hand Power" instead of
"Powerful Hand", effect correct), Dragapult ex TWM 130 (Phantom Dive 200 + 6 counters on Bench,
Tera bench protection), Mega Kangaskhan ex MEG 104 (Run Errand once per turn from Active, flip until
tails +50), Battle Cage PFL 85 (blocks opponent's attack/ability counters on Bench), Unfair Stamp TWM
165 (only after a KO on the opponent's last turn; 5/2 redraw), Rare Candy MEG 125 (format override
to the SVI implementation; blocks first turn and Pokémon played this turn) all match the printed
text. Chi-Yu TWM 39 is implemented but missing from Twinleaf's set export (the runner registers it).
No card we checked was wrong; the gap is bot play, not rules.
