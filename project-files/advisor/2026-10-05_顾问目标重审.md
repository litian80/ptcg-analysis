# 按"竞赛顾问"重新审视项目（2026-10-05）

目的（T 原话）：一个 Pokemon TCG 竞赛顾问，提供有效的卡组选择建议，以及选中卡组的打法和对各种对手的对局建议。

## 一句话结论

材料已经够多，缺的是"出口"：现在的东西是一堆研究资料（报告、60 份长手册、75 场复盘、台账），
还没有一个面向下一场比赛、几分钟能读完的顾问输出。下一步应该先做"赛前简报"，而不是再加资料。

## 顾问的三块和现状

| 顾问要回答的 | 现在有什么 | 够不够 |
|---|---|---|
| **该带哪套卡组** | `ptcg.selection`：按大赛对位胜率和 Day 2 环境算期望胜率；10-04 报告（首选 Basic Box） | 半够。数字每周自动更新，但文字报告是手写的，会过期；它回答的是"上一场的环境里谁最好"，不是"下一场会遇到什么" |
| **这套卡组怎么打** | 12 个主流卡组的 game plan（`data/archetypes/`） | 够用 |
| **对每个对手怎么打** | 5 套推荐卡组 × 12 个对手 = 60 份手册，75 场录像复盘支撑，关键判断带信心概率 | 内容够，形式不行：每份 60 到 110 KB，比赛前没人读得完（Joe 的反馈） |
| 卡表怎么针对环境微调 | `tech_TEF-30C.json` 里有"带不带某张卡"的胜率差，但没整理成建议 | 有数据，没产品 |
| 下一场环境的预判 | 没有 | 缺（Joe 最想要的） |

支撑层（不直接面向用户，但让建议可信、能进化）：每周数据管线、判断台账和反馈机制、复盘检查清单、PTCGL 对局解析器（PR #6，未合并）。

## 优先级建议

**第一：赛前简报（把现有东西变成顾问输出）**
每场目标比赛一份，一两页：
1. 预计会遇到的环境（前 8 个卡组和份额）；
2. 推荐卡组和理由，各配一句"适合谁"；
3. 推荐卡组的卡表微调：换哪几张、针对谁、代价（就是之前的方向 1）；
4. 对每个主流对手 3 到 5 条要点，关键决策写清场面（就是之前的方向 3，加上 Joe 指出的盲点）；
长手册留着查，简报里链过去。
同时把选卡组报告改成每周数据更新后自动生成，不再手写过期。

**第二：下一场环境预判**
简单可解释的模型：份额走势 + 上一场冠军/前 8 卡组带来的跟风 + 针对它的卡组上升。
可以在现有 2026 赛季 41 场比赛里逐场回测（用前几场预测下一场，看准不准），不需要扩到往年数据。
预判结果直接喂给第一项的"预计环境"和选卡组的期望胜率。

**第三：按需补手册**
现在只有 5 套推荐卡组有对局手册。顾问推荐了新卡组，或者你决定自己要打哪套（比如你现在打的 Alakazam Dudunsparce），再给那套补手册，不一次铺满。

## 可以放一放

- **高手选卡组统计**（之前的方向 2）：对你"学习高手怎么想"有价值，但不直接产出建议。可以等第二项需要信号时，作为一个输入（高手早期改用什么卡组）顺手做。
- **模拟对战**（Joe 的理想工具）：需要完整的规则引擎，工作量远超其余所有项目，先不做。
- **用往年数据回测 rotation**：要把数据范围扩到 2026 赛季以前，和你定的范围冲突；第二项先在赛季内回测，效果好再考虑。
- **录像复盘**：积压已清完，以后只跟新比赛。
- **PTCGL 解析器（PR #6）**：服务于复盘你自己的对局，不是顾问主线，可以先合并放着。

## 要你定的

1. 优先级是否按上面的顺序（推荐：先做赛前简报）。
2. 简报的目标比赛：默认下一场有数据的大赛；如果你在准备某场具体的比赛，告诉我是哪场。
